Lightweight architecture decision records for Video Factory. `PHASES.md`
is the execution authority; this file records decisions made while
executing it, especially ones not fully specified by the plan itself.

## ADR-001: Standalone git repository, isolated from an unrelated parent workspace

**Date:** 2026-10-09
**Status:** Accepted

**Context:** This project's working directory was initially located beneath an unrelated
parent workspace containing unrelated material.
PHASES.md requires this project to become its own public GitHub repository
with clean, phase-based commit history and strict secret/PII hygiene.

**Decision:** Run `git init` inside the project directory itself. This
project's history is fully independent of the parent workspace.

**Consequence:** Phase commits here never touch or risk exposing anything
from the parent workspace.

## ADR-003: One `domain` package for core data contracts; small per-concern packages for behavior

**Date:** 2026-10-09
**Status:** Accepted

**Context:** PHASES.md section 5 lists all core data types together under
one "Core Domain Model" heading. PHASES.md section 19 separately asks for
small, capability-specific interfaces rather than one large interface.

**Decision:**
- All pure data contracts from section 5 live in `domain`.
- Behavioral interfaces that consume `domain` types live in their own
  small packages: `provider`, `decision`, `resource`, `event`.

**Consequence:** No duplicate/divergent type definitions across packages;
no "god interface"; package-qualified names stay idiomatic
(`provider.Provider`, not `provider.ProviderProvider`).

See `ARCHITECTURE.md` for the full rationale.

## ADR-004: Open string vocabularies instead of closed enums for categories/capabilities

**Date:** 2026-10-09
**Status:** Accepted

**Context:** PHASES.md repeatedly requires provider/model/flow/framing
independence (sections 4.1, 4.2, 7) and explicitly says shot categories in
section 6 are "recommended," not exhaustive.

**Decision:** `ShotCategory`, `PrimitiveType`, `AssetKind`, and capability
tags (`ProviderCapabilities.Tags`, `ModelCapabilities.Tags`) are typed
strings with exported constants for the known/recommended values, not
closed Go enums (`iota`-based types restricted to a fixed set).

**Consequence:** Later phases/providers can introduce new categories,
primitives, or capability tags without modifying `domain`. The tradeoff is
weaker compile-time exhaustiveness checking, which is acceptable given the
explicit pluggability requirement.

## ADR-006: `decision.Policy` included in Phase 00 as a pure value type, not a decision engine

**Date:** 2026-10-09
**Status:** Accepted

**Context:** PHASES.md section 8 gives a concrete, deterministic threshold
example (`score >= 0.85 -> YES`, `score <= 0.30 -> NO`, otherwise
`UNCERTAIN`) as part of describing decision *contracts*. Phase 06 owns the
full Decision Engine (provider registry, fallback/escalation policy).

**Decision:** Phase 00 includes `decision.Policy` / `decision.Evaluate` as
a small, pure, provider-agnostic value type satisfying the "decision
contracts" TODO item, without implementing provider routing, registries,
or escalation — that scope stays in Phase 06.

**Amendment (same date, prompted by Phase 00 review #1/#2):** `Evaluate`
alone silently accepted inverted/out-of-range/non-finite thresholds
(e.g. `YesThreshold < NoThreshold`), producing a plausible-looking but
wrong verdict instead of a detectable error. Added `Policy.Validate()
error`, which callers constructing a `Policy` from configuration must
call; `Evaluate` itself remains a pure, side-effect-free function and
still does not validate (so it stays trivially composable), but its doc
comment now says so explicitly.

## ADR-007: Duration/timing serialization and relativity conventions

**Date:** 2026-10-09
**Status:** Accepted
**Prompted by:** Phase 00 review #1 (terra) and #2 (astra) — both flagged
undocumented duration units and ambiguous timing relativity.

**Context:** `domain` has two different kinds of time values: positions
on the video timeline (`Shot.Duration`, `TimelineEntry.Start/End`,
`VisualElement.Start/End`, `ReviewFeedback.Timestamp`) and real-world
operation timings (`GenerationResult.DurationMs`). Left undocumented,
`time.Duration`'s default JSON encoding (integer nanoseconds) and the
relativity of each timestamp (shot-relative vs. project-relative) were
ambiguous across packages.

**Decision:**
- Video-timeline positions use `time.Duration`, serialized by
  `encoding/json` as integer nanoseconds.
- Real-world operation timings use explicit `...Ms int64` fields
  (`GenerationResult.DurationMs`) instead, since they cross future
  process/worker boundaries where millisecond precision is sufficient
  and an explicit field name avoids re-deriving units.
- `TimelineEntry.Start`/`End` are project-timeline-relative.
- `VisualElement.Start`/`End` are shot-relative (0 = start of the shot
  named by `ShotID`), matching the per-shot `RenderManifest` convention.
- `ReviewFeedback.Timestamp` is shot-relative when `ShotID` is set,
  otherwise project-relative.
- All intervals are end-exclusive: `[Start, End)`.
- `Bounds` are normalized `[0,1]` coordinates, origin top-left.

These conventions are recorded as doc comments on the relevant types in
`domain/timeline.go`, `domain/visual.go`, and `domain/review.go`, and
exercised by `domain/domain_test.go`.

## ADR-008: `map[string]any` extension fields use plain JSON values; no schema in Phase 00

**Date:** 2026-10-09
**Status:** Accepted
**Prompted by:** Phase 00 review #2 (astra) — flagged that
`Properties`/`Payload`/`Input`/`Metadata` fields have no defined,
lossless JSON contract (e.g. large integers losing precision through
`float64`).

**Context:** Several contracts (`Primitive.Properties`,
`Change.Payload`, `DecisionRequest.Input`, `Asset.Metadata`, event
`Payload`) use `map[string]any` for open-ended extension data.
`encoding/json` decodes all JSON numbers in `any` fields as `float64`,
which loses precision for integers outside `float64`'s exact range.

**Decision:** For Phase 00, these fields are documented as holding
JSON-compatible values only, with the standard `encoding/json`
`float64`-for-numbers decoding behavior as the accepted default. No
schema validation or alternate numeric decoding (`json.Number`,
`UseNumber`, typed payloads) is introduced yet.

**Consequence / follow-up:** If a later phase needs lossless large
integers or typed payload validation (e.g. the Phase 02 event-worker
protocol, or Phase 13 ChangeSet mutation semantics), it must introduce
that handling explicitly at that boundary; callers should not assume
exact integer precision through these fields today.

## ADR-009: ULID IDs via a dedicated `idgen` package; path-traversal guard in `FileStore`

**Date:** 2026-10-09
**Status:** Accepted (encoding corrected same day after Phase 01 review)

**Context:** Phase 00 ADR-005 deferred ID generation strategy to
Phase 01. Phase 01 also introduces the first real persistence code
(`project.FileStore`), which derives filenames from `domain.Project.ID`.

**Decision:**
- IDs are generated by a new, dependency-free `idgen` package as
  standard ULIDs (https://github.com/ulid/spec): 48-bit millisecond
  timestamp + 80 bits of `crypto/rand` randomness, encoded as 26
  characters of Crockford Base32 with the spec's 2 leading zero padding
  bits. This keeps IDs sortable by creation time, collision-resistant,
  stdlib-only (PHASES.md section 4.9), and interoperable with standard
  ULID decoders.
  - **Correction (same-day Phase 01 review):** the first implementation
    padded the *end* of the bitstream with zeros instead of prepending
    2 padding bits before the data, as the ULID spec requires. This
    produced IDs that were internally sortable and unique but not
    decodable by a standard ULID library (e.g. the first character
    could be any of `0`-`Z`, not just `0`-`7`). Fixed in `idgen.encode`;
    pinned with `TestEncodeKnownVector` and
    `TestNewFirstCharacterIsWithinULIDRange` so it can't silently drift
    again.
  - A failed read from the OS CSPRNG is treated as fatal and surfaced
    (`newAt` returns an error; `New` panics), not silently replaced with
    a predictable/zero fallback — the original design's "fall back to
    zero randomness" rationale was wrong: a failure in the same
    millisecond would make a collision *certain*, not "extremely
    unlikely." The random source is an injectable package variable
    (`randReader`) solely so this failure path has a test
    (`TestNewPropagatesEntropyFailure`).
- `idgen.New()` is the module-wide ID-minting authority; any package may
  call it directly. `project.NewID()` is only a thin convenience wrapper
  used by this package's own constructors, not a required indirection
  for unrelated packages.
- Because a `domain.Project.ID` is, in principle, caller-supplied data,
  `project.FileStore` validates every ID against a conservative
  allow-list (`^[A-Za-z0-9_-]+$`) before deriving a filename from it,
  rejecting path separators and `..` segments. This is a defense-in-depth
  measure: today's only ID source (`idgen`) already produces safe
  strings, but a future caller/API (e.g. a Phase 12 TUI command, or a
  Phase 05 Director-provided ID) might not.

**Consequence:** `FileStore.Load`/`Save` return an error instead of
reading/writing outside the intended store directory for any ID shaped
like a path-traversal attempt. Generated IDs are genuine ULIDs usable
with any standard ULID tooling.

## ADR-010: `domain.Project` owns `Timeline` and `Assets`, not just `Plan`

**Date:** 2026-10-09
**Status:** Accepted
**Prompted by:** Phase 01 review #1 (sol, BLOCKER) and #2 (luna6, HIGH)
— both independently identified that the persisted `Project` aggregate
excluded `Timeline` and `Asset` state, so saving/loading a project
silently discarded any timeline or assets built in memory, contradicting
the phase's own name ("Project State / Timeline") and Required Result.

**Context:** Phase 00 modeled `Project`, `VideoPlan`, `Timeline`, and
`Asset` as related but structurally separate types (`Timeline` carries
its own ID and a `ProjectID` back-reference; `Asset` carries only its
own ID and media metadata, with no back-reference — it was always meant
to be owned by whatever contains it). `Project` itself only embedded
`*VideoPlan`, so `project.FileStore`, which persisted exactly one
`domain.Project` value, never saved anything not reachable from that
value.

**Decision:** Add `Timeline *domain.Timeline` and `Assets []domain.Asset`
fields to `domain.Project`, following the same optional-pointer pattern
already used for `Plan`. `project.Validate` now also validates the
embedded `Timeline` (ID, `ProjectID` linkage, and `ValidateTimeline`
against the plan's shots, including that every `VisualElement`'s shot is
actually placed on the timeline) and the embedded `Assets` (ID
uniqueness, required `Kind`/`URI`) as part of validating a `Project`.

**Consequence:** A `Project`'s plan, timeline, and assets now round-trip
through `Marshal`/`Unmarshal`/`FileStore` together, as one consistency
boundary, matching "a project can be created, loaded, modified, saved,
and validated" (PHASES.md Phase 01 Required Result). `domain.Timeline`
keeps its own ID and `ProjectID` back-reference so it remains
independently meaningful (e.g. for a future API that returns just a
timeline); `domain.Asset` is owned purely through `Project.Assets`. Both
are no longer orphaned by persistence.

## ADR-011: Typed sentinel errors and identity verification in `FileStore`

**Date:** 2026-10-09
**Status:** Accepted
**Prompted by:** Phase 01 review #1 (sol) and #2 (luna6) — both flagged
that `Load` never checked the decoded project's ID against the requested
ID, and that corrupt-data/invalid-project failures were only
string-wrapped, not classifiable with `errors.Is`.

**Decision:**
- Added `ErrCorrupt`, `ErrInvalid`, and `ErrIdentityMismatch` sentinel
  errors (alongside the existing `ErrNotFound` and
  `ErrUnsupportedSchemaVersion`), all wrapped with Go 1.20+'s
  multi-`%w` `fmt.Errorf` so `errors.Is` works alongside a human-readable
  message and the underlying cause.
- `FileStore.Load` now rejects a file whose decoded `Project.ID` does
  not equal the requested ID (`ErrIdentityMismatch`), so a copied,
  renamed, or hand-edited file cannot cause `Load(A)` to silently return
  project `B`.
- `FileStore.Save`/`Load` now document their concurrency contract
  explicitly on the `Store` interface: safe for concurrent use across
  distinct IDs; same-ID concurrent `Save`s are last-writer-wins with no
  built-in optimistic-concurrency check (callers needing conflict
  detection must build it on top, e.g. comparing `UpdatedAt`).
- `FileStore.Save`'s atomic write was strengthened: the temp file is
  `fsync`'d before `Close`/`Rename` (not just written), and the store
  directory is best-effort `fsync`'d after the rename (ignored if the
  underlying filesystem doesn't support directory `fsync`, since the
  rename itself already made the write visible).

**Consequence:** Callers can use `errors.Is(err, project.ErrInvalid)`
etc. instead of string matching. `Load` cannot return a project under
the wrong identity. Save durability is closer to "survives a crash
immediately after Save returns," not just "atomic from a concurrent
reader's point of view."

## ADR-012: Second Phase 01 review round — timeline/element placement, asset validation, flow/framing presence

**Date:** 2026-10-09
**Status:** Accepted
**Prompted by:** a confirmation re-review from the same two reviewers
(sol, luna6) after ADR-009/010/011 landed. Both independently found
further gaps the first round of fixes didn't cover.

**Decision:**
- `ValidateTimeline` now requires every `VisualElement`'s shot to
  actually have a `TimelineEntry` (not merely be a *known* shot).
  Without this, an element could pass validation while being
  unreachable from `EntryForShot`/`AbsoluteStart`, breaking the
  element-to-shot/timeline relationship (PHASES.md section 4.6.1).
- `ValidateTimeline` now requires a `TimelineEntry`'s placed duration
  (`End - Start`) to equal its shot's declared `Duration` exactly —
  the data model has no separate trim/retiming concept yet, so letting
  the two disagree would leave two conflicting "true" durations for the
  same shot.
- `Validate` now validates `Project.Assets`: non-empty, unique IDs, and
  required `Kind`/`URI`.
- `validatePlan` now requires non-empty `VideoPlan.FlowID` and
  `FramingID`. This checks only that *a* reference is present, not that
  it resolves against a registry (registries are Phase 04 scope).
- `BuildDependencyGraph` now deduplicates repeated dependency edges on
  the forward (`dependsOn`) side too, matching the dedup already applied
  to the reverse (`dependents`) side.
- `FileStore.Load` re-checks `ctx.Err()` immediately after reading the
  file (in addition to the entry check), so a cancellation that occurs
  during the read is observed before doing any further work.
- Fixed a stale test comment/assertion in `idgen_test.go`: with standard
  ULID padding, the first **10** characters (not 9) are purely
  timestamp-derived (48 timestamp bits + 2 padding bits = 50 bits = 10
  Base32 characters exactly), so two IDs minted in the same millisecond
  must share all 10, not 9.
- Corrected ADR-010's wording: `domain.Asset` has no `ProjectID`
  back-reference (only `domain.Timeline` does); `Asset` is owned purely
  through `Project.Assets`.

**Consequence:** The remaining gaps identified in the confirmation
review are closed; both reviewers' structural-validation and
documentation-accuracy concerns are addressed without expanding scope
into registry validation (Phase 04) or non-recursive graph traversal
(left as a documented, accepted limitation for Phase 01's trusted-input
scope).

## ADR-013: `event.Bus` ordering/backpressure/cancellation design

**Date:** 2026-10-09
**Status:** Accepted

**Context:** Phase 00/01 defined `event.Type`, `event.Event`, and the
`Publisher`/`Subscriber` interfaces, but deferred the actual pub/sub
implementation to Phase 02, which explicitly requires defined
cancellation, backpressure, and ordering semantics (not just "an event
bus").

**Decision:**
- **Ordering:** a single mutex serializes `Seq` assignment and dispatch
  in `Publish`. `Seq` (added to `event.Event`), not `OccurredAt`, is the
  authoritative total order, since wall-clock timestamps from
  concurrent goroutines aren't guaranteed strictly increasing at
  whatever resolution the platform clock offers.
- **Backpressure:** per-subscriber dispatch is non-blocking
  (`select`/`default`); a full subscriber channel causes drop-newest
  for that subscriber only, counted in a bus-wide `TotalDropped()`.
  Rejected alternative: blocking `Publish` until every subscriber has
  room, which would let one slow consumer (e.g. a laggy TUI) stall
  generation/validation elsewhere in the system — directly contradicts
  PHASES.md section 11.
- **Cancellation:** each `Subscribe` call spawns one goroutine that
  waits on *either* its own `ctx.Done()` or a bus-wide `closedCh` (closed
  once by `Close`), then unsubscribes. Rejected alternative: watching
  only `ctx.Done()`, which would leak a goroutine per
  `context.Background()` subscription forever once the bus is closed.
- **Event metadata:** `Publish` fills in `ID`/`OccurredAt` when the
  caller leaves them zero, rather than requiring every caller to
  hand-stamp both on every event, while still respecting explicit
  caller-supplied values (needed for deterministic tests).
- Scope boundary: `Bus` is in-process only, with no persistence,
  replay, or cross-process transport — those are future-phase concerns
  (e.g. a Lambda/control-plane event transport) layered behind the same
  `Publisher`/`Subscriber` interfaces if ever needed, not something
  Phase 02 should pre-build.

**Consequence:** `Bus` is small, lock-protected, leak-free, and has
concrete, tested guarantees (`event/bus_test.go`) rather than vague
"events happen" semantics — satisfying PHASES.md Phase 02's explicit
"test event ordering guarantees" / "document ordering semantics" /
"test concurrent subscribers" TODO items with real tests, not just
comments.

## ADR-014: Phase 02 review round — cancellation re-check, payload contract, and test-suite correctness fixes

**Date:** 2026-10-09
**Status:** Accepted
**Prompted by:** Phase 02 review #1 (astra). Review #2 (gpt-oss-120b)
found no additional issues; astra's findings were the substantive ones
and are recorded here.

**Decision:**
- `Publish`/`Subscribe` now re-check `ctx.Err()` (and `Bus.closed`)
  immediately after acquiring the internal mutex, not only at entry, so
  a caller whose context was cancelled while waiting for the lock
  doesn't still get an event dispatched or a subscription registered.
- Documented the payload-ownership contract explicitly on `Event` and
  `Bus`: `Payload` is shared by reference across subscribers, not
  deep-copied, so callers must treat it as immutable once passed to
  `Publish`. Not enforced by copying (that would cost real throughput
  for a benefit most callers don't need), just specified.
- Fixed a real bug in the test suite, not production code: several
  tests called `t.Fatalf` from goroutines other than the one running
  the test, which the `testing` package explicitly disallows for
  `Fatal`/`FailNow` (unlike `Error`, which is safe from any goroutine).
  `drain` was split into a goroutine-safe `drain` (returns `error`) and
  a `mustDrain` convenience wrapper (calls `t.Fatalf`) used only from
  the test's own goroutine; spawned goroutines now report errors
  through a channel instead.
- Strengthened `TestBusOrderingGuarantee` and
  `TestBusConcurrentPublishersPreserveTotalOrder` to assert the *exact*
  `Seq` sequence `1..n` (not just "no duplicates"), and added a start
  barrier to the concurrent-publishers test to maximize lock contention
  instead of relying on incidental goroutine scheduling.
- Replaced the misleading part of the goroutine-leak test: observing
  only that a subscription's channel closed after `Bus.Close()` doesn't
  prove its *watcher goroutine* exited, since `Close` closes the
  channel itself directly in its own loop regardless of the watcher.
  `TestBusCloseDoesNotLeakBackgroundContextWatchers` now counts live
  goroutines (`runtime.NumGoroutine()`) before and after `Close`.
- Removed a self-inflicted test-robustness hazard in
  `TestBusBackpressureDropsNewestWithoutBlocking`: it no longer defers
  `Close()`, because if `Publish` ever regressed to blocking while
  holding the mutex, that `defer` would make `Close()` block too,
  turning a fast, clear test failure into a hung test binary.
- Corrected a citation: "no uncontrolled goroutines" is in PHASES.md
  section 4.10 (Lambda awareness), not 4.9, in both `bus.go`'s comment
  and `ARCHITECTURE.md`.
- **Follow-up fix (same reviewer, second pass):** the leak test's
  initial tolerance (`before + n/2`) would still pass with up to half
  of `n` watcher goroutines leaked, defeating its purpose. Tightened to
  a small fixed constant (`leakTolerance = 10`), and verified the test
  actually catches a real leak by temporarily reintroducing one (the
  watcher goroutine watching only `ctx.Done()`, not `closedCh`): the
  test failed with "before=2, after=202 (leaked watcher goroutines)" as
  expected, then passed again once the real code was restored.

**Consequence:** The Bus's correctness guarantees are now backed by
tests that would actually fail if those guarantees regressed, and the
test suite itself follows the `testing` package's own concurrency
rules.

## ADR-015: `render` package shells out to `ffmpeg`/`ffprobe` via `os/exec`

**Date:** 2026-10-09
**Status:** Accepted

**Context:** Phase 03 needs an "FFmpeg integration strategy" — a
decision this module hadn't made yet. PHASES.md section 2.1 explicitly
endorses native tools ("Use native executables where appropriate:
FFmpeg, FFprobe, OpenCV") and separately describes a Go-core-manages-
external-process pattern for Python workers that generalizes cleanly to
any native tool.

**Decision:** The `render` package builds a deterministic ffmpeg
filter graph and command line from `domain` types in Go, then invokes
the external `ffmpeg`/`ffprobe` binaries via `os/exec` with
`context.Context` (so cancellation kills the process), rather than
linking against libav via cgo bindings.

**Rejected alternative:** cgo/libav bindings. Rejected because they add
build complexity (a C toolchain and libav headers become required to
even `go build`), hurt portability (version-matching libav across
platforms), and aren't needed — the CLI tools expose everything Phase
03 needs. This matches PHASES.md section 4.9's "no unnecessary
dependencies."

**Consequence:**
- `ffmpeg`/`ffprobe` are a **system dependency**, not a Go module
  dependency; they must be installed separately (see `README.md`).
- Tests that need them skip gracefully (`requireFFmpeg`/
  `requireDrawtext`/`requireFontPath` in `render/testhelpers_test.go`)
  rather than failing on a machine without them, since this is public,
  cross-contributor code.
- A plain `ffmpeg` build without `libfreetype` can still render
  Background/Image-only shots; only Text primitives need `drawtext`
  (and therefore `libfreetype`). On this development machine, the
  default Homebrew `ffmpeg` formula didn't include `drawtext`; the
  `ffmpeg-full` formula does (and happens to also bundle `libass`,
  useful for Phase 11's subtitles later).

## ADR-016: `drawtext` text/path escaping abandoned in favor of controlled temp files

**Date:** 2026-10-09
**Status:** Accepted (superseding an earlier same-day version of this
ADR — see "History" below)

**Context:** ffmpeg's filtergraph description syntax has its own
escaping rules, and they are easy to get wrong from memory/documentation
skimming alone. The first implementation of `escapeDrawtext` prefixed a
backslash before `\`, `:`, and `'` uniformly — which looked reasonable
but was wrong, and the failure mode was confusing: ffmpeg didn't reject
the single quote; it corrupted parsing of the *next* filter option
("expansion"), producing the misleading error `Unable to parse
"expansion" option value "none[v1]"`.

**History of this ADR (both superseded by the final decision below):**

1. **First attempt:** backslash-escape `\`, `:`, and `'` uniformly.
   Wrong — broke parsing of the following option (see above).
2. **Second attempt (same day):** wrap the value in single quotes and
   use `\\`/`\:`/`'\''` (the POSIX-shell-style close/escape/reopen
   trick for the embedded quote). This *parsed without error* and was
   initially believed correct and "empirically verified." It was not:
   building the Phase 03 pixel-sampling tests (prompted by review
   feedback that metadata-only checks don't prove anything visual
   actually rendered) revealed that **any text containing an
   apostrophe via this trick rendered as completely empty text** —
   `ffmpeg` exited `0` with no error, but zero pixels differed from
   the background. The same trick applied to a font *path* containing
   special characters also broke parsing of the following
   (`textfile=`) option entirely, differently from the text case. This
   is a correctness bug, not just a leftover security concern: trusting
   "no error" as proof of correctness was itself the mistake.

**Decision (final):** Stop embedding caller-controlled strings into the
filter_complex string's option values at all, for both text content and
the font path:

- Text content is written to a temp file and referenced via
  `drawtext`'s `textfile=` option instead of `text=`. `textfile` reads
  raw file content with no filtergraph-level escaping of the text
  itself required, which sidesteps the whole class of bug — including
  letting multi-line text work for free (no longer rejected).
- `Settings.FontPath` (however the caller supplied it) is copied, by
  content, to a new temp file in a freshly created temp directory with
  a fixed, Go-generated filename (`font.ttf`). The *generated* path is
  what gets embedded in `fontfile=`, never the original string.
- Both generated paths are checked against `checkFilterGraphSafePath`
  (rejecting `:`, `'`, `\`, `;`, `,`, `[`, `]`) before use, as a defense
  check against a pathological `TMPDIR`, even though `os.CreateTemp`/
  `os.MkdirTemp` paths satisfy this in practice.
- `filterPlan` now carries `cleanup []func()` for these temp
  files/directories; `FFmpegRenderer.RenderShot` defers running them
  after the ffmpeg command finishes (success or failure), and
  `buildFilterGraph` itself cleans up anything it already created if it
  returns an error partway through.

This also resolves the original security motivation (a `FontPath`
containing filtergraph syntax characters injecting additional filter
stages — confirmed exploitable in review): the font file is never
referenced by its original, potentially attacker-influenced path at
all, so there is nothing left to inject through.

**Regression tests:**
`TestRenderShotText` now asserts actual rendered pixels (not just "no
error"), using text containing both `:` and `'` together, and would
have caught this bug — it did, during development, before this fix
landed. `TestFontPathInjectionIsNeutralized` and
`TestPrepareSafeFontFileNeutralizesSpecialCharactersInOriginalPath`
cover the path-injection angle specifically.

**Consequence:** Text containing `:`, `'`, `\`, or multiple lines
renders correctly. The lesson generalizes: for any future primitive/
filter that would otherwise embed a caller-controlled string into an
ffmpeg filtergraph description, prefer a file-based option (`textfile`-
style) or a controlled-location copy over escaping-in-place, and verify
rendered *pixels*, not just absence-of-error, before trusting an
escaping scheme.

## ADR-017: Flow/Framing/Primitive registries as mutex-protected structs with `AssignSlots` as the only composition entry point

**Date:** 2026-10-09
**Status:** Accepted

**Context:** Phase 04 asks for Flow/Framing/Primitive registries with
capability declarations, and explicitly: "ensure framing is not
embedded into business logic." `domain.Flow`/`domain.Framing` already
existed (Phase 00) as pure data with no registry/lookup mechanism and
no actual layout (`Framing` had no concept of where content goes).

**Decision:**
- `domain.Framing` gained `Slots []FramingSlot` (name + normalized
  `Bounds`, ADR-007's convention) — the framing's *layout* becomes real
  data, not just a label. `domain.Flow` gained `DefaultFramingID` and
  `RecommendedCategories` as advisory metadata for a future Director
  (Phase 05), not enforced by this phase.
- Three registries (`FlowRegistry`, `FramingRegistry`,
  `PrimitiveRegistry`) are plain mutex-protected structs, not
  package-level global singletons — consistent with this module's
  existing style (`project.FileStore`, `event.Bus`) and PHASES.md
  section 4.9's "no hidden global mutable state." Each is seeded with
  built-in entries by its `NewXRegistry()` constructor and open to
  `Register()` of more at runtime.
- `registry.AssignSlots(framing, content)` is the single function that
  applies a Framing's layout to a set of named content primitives. It
  reads only `framing.Slots`; it contains no `switch`/`if` on any
  specific `FramingID` anywhere. This is the literal mechanism by which
  "framing is not embedded into business logic" is satisfied, not just
  asserted: `TestAssignSlotsWorksForARuntimeRegisteredFramingWithNoCodeChanges`
  registers an entirely new framing at runtime and runs it through the
  same, unmodified function.
- `domain.PrimitiveCapabilities` reuses the `Tags`-based capability
  pattern from `ProviderCapabilities`/`ModelCapabilities` (Phase 00),
  rather than inventing a different shape — classifying every
  `PrimitiveType` as deterministic or AI-capable per PHASES.md section
  6, independent of whether `render` (Phase 03) currently implements
  it. A dedicated test
  (`TestPrimitiveRegistryMatchesRenderPackageExpectations`) pins the
  four entries `render` *does* implement to its actual behavior, so
  the registry's metadata and the renderer's real behavior can't
  silently drift apart.

**Rejected alternative:** package-level global registry variables
(e.g. `var DefaultFlowRegistry = ...`). Rejected for the same reason
`event.Bus`/`project.FileStore` aren't globals either: hidden global
mutable state makes testing and future multi-tenant/control-plane use
(PHASES.md section 4.10) harder, for no real benefit — callers that
want a shared instance can construct one and pass it around.

**Consequence:** Adding a new Flow, Framing, or Primitive capability
declaration is a `Register()` call; it never requires modifying
`AssignSlots` or any renderer. `render` (Phase 03) was confirmed to
contain zero Framing-related conditional logic (only a plain string
value in one test fixture), so this phase didn't need to touch it.

**Amendment (same date, prompted by Phase 04 review #1 (terra) and #2
(sol6), both independently):**

1. **Slice aliasing defeated the mutex.** `Register`/`Get`/`List`
   stored and returned values that shared backing arrays with
   caller-owned slices (`Flow.RecommendedCategories`,
   `Framing.Slots`, `PrimitiveCapabilities.RequiredProperties`/`Tags`).
   A caller mutating a value returned by `Get` — or mutating the value
   they passed to `Register`, after the call returned — could
   silently corrupt the registry's internal state, racily, since the
   mutex only ever protected the map itself, never the aliased slice
   contents. **Fix:** every registry now defensively copies these
   slice fields on both `Register` (so the stored copy can't be
   affected by later caller-side mutation) and `Get`/`List` (so the
   caller's copy can't affect the registry). Verified by deliberately
   reverting the fix for `FlowRegistry` and confirming
   `TestFlowRegistryIsolatesSliceFieldsFromCallerMutation` failed with
   `"mutating the slice passed to Register affected the stored
   entry"`, then restoring it and confirming the test passed again.
2. **`FramingRegistry`'s bounds validation accepted `NaN`/`Inf`.**
   `validateSlotBounds` used only relational comparisons, which are
   silently `false` for `NaN` operands — despite ADR-017's original
   text claiming it matched `render`'s `validateBounds`, which does
   check finiteness. **Fix:** added the same `math.IsNaN`/`IsInf`
   checks `render/properties.go` uses, for all four `Bounds` fields.
3. **`RequiredProperties` for `Background`/`Transition` contradicted
   `render`'s actual behavior.** `render/filtergraph.go` supplies a
   default for `Background`'s `color` and `Transition`'s `style`
   (neither is actually required to produce valid output), but the
   registry listed both as required, and the test that was supposed to
   catch drift between the two only checked the registry against
   itself. **Fix:** removed both from `RequiredProperties`; the test
   now explicitly asserts `Background`/`Transition` have *no* required
   properties, documenting *why* (they default) rather than just
   asserting a literal.
4. **The composition "proof" tests were not rigorous enough.** The
   generic all-framings test used `Background` (which `render` ignores
   bounds for) and only checked that a `"bounds"` key was present, not
   that it was the *correct* slot's bounds; the custom-framing test
   checked exact bounds for only the first of three slots. Either
   could pass with an implementation that assigned the wrong slot's
   bounds to a primitive. **Fix:** both tests now use bounds-aware
   `Image` primitives and assert every slot's exact bounds,
   index-aligned against `framing.Slots`.
5. Minor: a doc comment referenced a nonexistent `composition_test.go`
   (the actual file is `compose_test.go`); fixed.

**Consequence of the amendment:** the registries' concurrency safety
claim is now actually true for every exported field, not just the map
structure; bounds validation can't admit non-finite geometry; the
primitive-capability/renderer-behavior consistency claim is backed by
a test that would fail if they diverged; and the composition tests
would catch a slot-bounds mix-up that the original versions could not.

## ADR-018: `FixtureDirector` — keyword/reading-pace heuristics, no AI, with an optional `PromptInterpreter` seam

**Date:** 2026-10-09
**Status:** Accepted

**Context:** Phase 05 asks for a Director that turns a prompt into a
`domain.VideoPlan`, with an explicit instruction: "Do not tightly
couple the Director to Claude, Qwen, Gemini, or any single model." It
also asks for a "deterministic fixture Director" and an "optional LLM
adapter interface" as separate TODO items.

**Decision:**
- `FixtureDirector` is the only `Director` implementation in this
  module. It decomposes a prompt into shots using fixed, documented
  rules — sentence-splitting on `.`/`!`/`?`, a fixed reading-pace
  constant (2.5 words/sec) for duration, and avatar keyword matching
  (regex word-boundaries to avoid false positives like "me" inside
  "demo") to decide whether a shot needs an AI avatar
  or can be deterministic Background+Text. None of this calls a model,
  a network, or any external process.
- `PromptInterpreter` is the *only* seam through which a smarter
  Director could use LLM assistance (a suggested Flow and/or shot
  hints). `FixtureDirector` optionally accepts one
  (`WithPromptInterpreter`) and merges its suggestions with the
  deterministic fallback for anything the interpreter didn't resolve,
  rather than requiring an interpreter or hard-coding any particular
  one. Empty hint lists permit fallback; supplied blank hints are errors,
  not missing suggestions. No production `PromptInterpreter` exists yet;
  model-backed assistance is later-phase work behind this seam,

  Deterministic code decides." (PHASES.md section 1).

  capability-tag pattern (`PrimitiveRegistry.Get(type).Tags`) rather
  than inventing a parallel vocabulary: the Director aggregates what
  capabilities a plan's primitives declare, it doesn't decide how to
  satisfy them (that's Phase 07's Provider Router).
- `project.ValidatePlan` was exported from Phase 01 so a Director can
  validate a `VideoPlan` before attachment to a `Project`. Its public
  boundary requires a nonempty expected project ID and matching
  `plan.ProjectID`, then delegates structural checks to internal
  `validatePlan`. It does not verify existence in project storage.
  `FixtureDirector.Plan` calls it before returning.

## ADR-019: Phase 06 decision execution and redacted best-effort audit policy

**Date:** 2026-10-09
**Status:** Accepted (implemented, reviewed, and final lead code gate verified)

**Context:** Phase 06 adds structured, pluggable classification over existing
contracts. The owner approved the execution policy in `PHASES.md` before
implementation. This ADR records that approval and its implementation boundary;
implementation presence does not establish phase completion.

**Decision:**

- Reuse `decision.Provider`, `provider.Provider`, and
  `domain.DecisionRequest`/`DecisionResult`; add no domain schema fields.
  Require a request ID and nonblank kind. No real model/vendor adapters,
  Director integration, or Phase 07 router are in scope.
- Score means affirmative likelihood, not confidence in the provider's
  verdict. Validate finite `[0,1]` scores and known YES/NO/UNCERTAIN verdicts;
  deterministic core recomputes classification from configurable thresholds:
  YES at `>= 0.85`, NO at `<= 0.30`, otherwise UNCERTAIN by default.

  hard limit of 8. Per-attempt timeout defaults to 5s; attempts per provider
  include the initial call, default to 2, and have a fixed hard cap of 3.

  cancellation-aware. Retry only child timeouts and explicitly classified

  to the next provider without retrying that uncertain result. Preserve the
  last valid UNCERTAIN if later providers fail or abstain; when all attempts

  nonsecret. Cancellation terminal publication may use separately bounded
  cooperative cleanup, never detached work.
- The bus/publisher is caller-owned. Existing event delivery is lossy and
  nondurable; add no persistence, queue, replay, or compliance-log promise.
  Defaults are configurable; the hard limits of 8 providers and 3 attempts
  remain fixed.

## ADR-020: Phase 07 snapshot registry and conservative metadata-only routing

**Date:** 2026-10-09
**Status:** Accepted delegated lead policy; implemented/reviewed; completion recorded in Phase 07 commit

- Routing is metadata-only. Keep `provider.Provider` unchanged; add missing

  hidden globals, detached work, or adapter calls under registry locks. Errors
  and rejection records use safe core codes; IDs/handles must be nonsecret.
  Do not include raw secret-bearing adapter strings in public diagnostics.
